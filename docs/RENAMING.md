# Автоматизация переименования

Скрипт `scripts/rename-project.mjs` выполняет локальную часть фазы 1 из
[исходного плана](RENAME_PLAN.md). Пока имя не выбрано, проект остаётся Relay.
Скрипт одноразовый: рассчитан на переход с исходного имени, а не на повторный ребрендинг.

## Когда имя выбрано

Сначала посмотреть отчёт — файлы проекта не меняются:

```sh
node scripts/rename-project.mjs --name callwing
```

Достаточно заменить `callwing` своим именем. По умолчанию получатся `Callwing`,
`CALLWING_*`, GitHub `callwing/callwing`, домен `callwing.dev` и идентификатор
приложения `dev.callwing.app`. Имя: 2–30 латинских строчных букв/цифр, первая — буква.
Ограничение позволяет использовать его внутри Go/JS-идентификаторов без нарушения синтаксиса.
При необходимости идентичность можно уточнить:

```sh
node scripts/rename-project.mjs --name callwing --display CallWing --org callwing-team --domain callwing.app
```

Для применения сначала сохранить текущие изменения коммитом или stash, затем:

```sh
node scripts/rename-project.mjs --name callwing --apply
```

Добавить `--verify`, чтобы автоматически собрать фронтенд и выполнить `make check`,
Go race-тесты, оба набора браузерных e2e, сборку сайта и проверку документации:

```sh
node scripts/rename-project.mjs --name callwing --apply --verify
```

Нужны установленные зависимости и браузеры Playwright. При сбое проверки инструмент
останавливается и сохраняет изменения для исправления и просмотра; успешно завершённые
проверки не означают готовность внешней инфраструктуры или графики.

Можно сохранить полный JSON-отчёт новым файлом вне репозитория:

```sh
node scripts/rename-project.mjs --name callwing --report /tmp/callwing-rename.json
```

Отчёт включает список файлов по категориям, переносы файлов, графические ассеты,
команды проверки и внешние шаги с подставленным именем. Режим `--apply` меняет
только локальные файлы: не создаёт релиз, не пушит, не меняет remote, DNS или аккаунты.

## Что меняется

- Go-модуль и импорты, npm workspaces и lockfile, сборки и CI, идентичность приложения.
- CLI, MCP, заголовки, протоколы, хранилище, переменные окружения, код и тестовые фикстуры.
- Расширение, сайт, документация, домен и ссылки GitHub.
- Имена файлов схемы, YAML-документации и знака приложения вместе со ссылками на них.
- Копия новой JSON Schema в `apps/web/public/schemas/`, чтобы сайт отдавал её по `$id`.
- Запись о переименовании в Unreleased; опубликованные записи changelog сохраняются.

Правила сначала обрабатывают полные идентичности (домен, организация, bundle ID),
затем регистры бренда и идентификаторы. Это включает косметические тестовые хосты.
Коллизии путей проверяются до записи. Предварительный просмотр включает незакоммиченные
неигнорируемые файлы; применение требует чистого дерева. Игнорируемые сборки,
локальные настройки, ключи, `.env` и симлинки не редактируются.
Скрипт и оба документа о переименовании остаются с исходными именами как инструкция
и история перехода. Старый префикс `/relay` в генераторе Pages-редиректов сохраняется,
чтобы входящие старые ссылки продолжали распознаваться.

## После применения

Просмотреть весь `git diff`, включая `git status` для новых имён файлов.
Переименованные бинарные картинки сохраняют прежние байты: новое имя не создаёт новый логотип.
Выбрать/заменить графику и выполнить напечатанные команды генерации и проверки.
`gen-appicon.mjs` рисует существующий знак; для другого логотипа нужно изменить его исходник.
Скриншоты и отдельные картинки сайта также требуют обновления.
`npm install --package-lock-only --ignore-scripts` сверяет lockfile с новым именем workspace.
После всех генераций повторить проверки, затронутые их результатом.

Сохранённый MSIX-сертификат может иметь старый Publisher: для подписи нужен сертификат
с новым subject или явное значение Publisher, совпадающее с существующим сертификатом.
Ключ расширения и ключ обновлений сохраняются; имена GitHub secrets/vars меняются отдельно.
Сгенерированные Windows-файлы, игнорируемые Git, нужно пересоздать сборкой Wails.

Проверить оставшиеся вхождения с учётом changelog, исходного плана, скрипта и старых редиректов:

```sh
rg -n -i relay --hidden -g '!.git/**' -g '!node_modules/**' -g '!**/dist/**' -g '!**/node_modules/**' -g '!.cache/**'
```

Финальная проверка: чистый запуск собранного приложения, воркспейс, CLI, MCP, обновления
и cookie-sync. Данные на своей машине, внешняя инфраструктура и фазы 0/2/3/4 остаются
отдельными шагами исходного плана. Покупка домена, товарные знаки, аккаунты, DNS,
магазины расширений и поисковики не могут выполняться только по имени без доступа к ним.

Проверка самого инструмента:

```sh
node --test scripts/rename-project.test.mjs
```
